# The Lapse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Owned words fall lit; dropping one puts the light out, shows only the reading you dropped with the Power-down voice, and queues the word to come back dark next wave, where clearing it relights it.

**Architecture:** The server stamps `owned` on each seen card in the run plan. The engine keeps a per-run light map and a comeback queue, stamps every airborne word with its spawn-time `light`, and tells the world through three widened events (`wordKilled.relit`, `wordMissed.lapse`/`light`, `gameOver.ownedIds`). The Pixi stage and the SFX player stay passive consumers: the stage reads `word.light` to pick the treatment, the lapse flicker, the reading-only reveal and the relight; the audio layer reads the event flags. A `comeback` boolean rides each attempt into SQLite, recorded and unread.

**Tech Stack:** TypeScript, Vite + React (HUD), PixiJS 8 (playfield), Web Audio (synthesised SFX), Hono + better-sqlite3 + Drizzle (API), zod 4 (shared schemas), vitest, Playwright (unchanged keystone e2e).

**Spec:** `docs/superpowers/specs/2026-10-24-the-lapse-design.md`

## Global Constraints

- **Colours only from the palette.** No hex or rgba literals in render code: `PALETTE.*` (`src/design/palette.ts`), which `tokenParity.test.ts` pins to `src/ui/tokens.css`. Dark words use `PALETTE.inkDim`; the lapse reveal uses `PALETTE.inkFaint`; the tag uses `PALETTE.danger`; the relit flash uses `PALETTE.accent`.
- **State renders at every effects level** (second-pass spec §6, §9.4). The reveal (every shape) is state: never create it inside an `if` that tests `haloAlpha`, `glowAlpha`, `flicker` or `effects` — `presenceInvariant.test.ts` parses `PixiStage.ts`/`WordSprite.ts` for exactly that. The flickers, the white core and the relit flash are decoration and may be gated.
- **Effects `off` is pixel-identical to today for plain and lit words.** Only `dark` differs at `off` (spec §6.1).
- **The engine is deterministic** under its seed and never touches the network; a run without a plan is today's game at spawn (spec §4.2).
- **Render and audio consume engine events only** (main spec §4). No engine import reads settings; no React component reads `word.light`.
- **No new design tokens.** Timings reuse `MOTION.snapMs` (90) and `MOTION.flareMs` (420). Adding a `MOTION`/`--duration-*` pair would need `tokenParity.test.ts` updated; the plan avoids it.
- **No stats, learned-gate, weight or tier changes.** `comeback` is written, never read.
- **Every task ends green:** `npm run check` (tsc -b, oxlint, vitest). On this Windows box run `npm`/`npx` from Git Bash (PowerShell's execution policy blocks `npm.ps1`), or use `npm.cmd`/`npx.cmd`.
- **Commit per task**, plain `git` commands, never stage `.claude/settings.local.json` or `.impeccable/`. Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- **Fixture rule:** `AirborneWord` and `AttemptEvent` each gain a required field in Task 1; every test fixture that builds one (`grep -rln "wasTargeted: false\|hintShown: " src server --include=*.test.*`: at least `src/data/__tests__/recorder.test.ts`, `src/engine/__tests__/matcher.test.ts`, `server/__tests__/runsRoutes.test.ts`) adds `light: 'plain', comeback: false` (words) or `comeback: false` (attempt events). Task 3 adds the DB column, so fixtures typed as the attempts row (`typeof attempts.$inferSelect`: `server/__tests__/cardScoring.test.ts`, `stats.test.ts`, `statsHelpers.test.ts`, `statsRoutes.test.ts`) add `comeback: false` there.

## Review Focus

1. **A no-plan run's replay** (`replayPlan(null, …)`) must light the cards that run killed; a server outage must not make "play again" flat. Pinned in Task 7.
2. **The lapse that ends the run** (lives hit 0 on the lapse itself): no comeback can happen, nothing throws, and `gameOver.ownedIds` still lists the card. Pinned in Task 5.
3. **A kana-only card lapsing in recall mode** has no kanji to put above the reading; the reveal must lay out without a kanji line and the lesson line must not start with a space. Pinned in Task 8.
4. **An events batch from an old client** (no `comeback` field, e.g. drained from the outbox after upgrade) must be accepted and stored as `false`. Pinned in Task 3.
5. **A seen pool of one card** that is also the comeback: `drawSeen` has nothing else to draw; the wave must be just the comeback, never a hang. Pinned in Task 4.
